# Session notes — 14–15 August 2026

Eighteen commits, `7b15f1d..22c1408`, 32 files, +5636/−540.

The session began with a bug report — "the mouse is blinking whenever the app
is open" — and ended with a distributable installer. Most of what follows was
found rather than planned.

## Bugs found and fixed

Listed first because they were the substance of the day, and because several
had been shipping silently.

**The cursor flickered system-wide whenever the app was open.** Instant Replay
restored its enabled state from the settings file, and its handler starts an
ffmpeg `gdigrab` capture of the whole desktop. GDI screen grabs force the
pointer to be redrawn, so the app was making the cursor flicker for as long as
it ran. Replay is no longer restored on launch: recording the screen is opt-in
per run, not a remembered setting.

**`HotkeySettings.Save()` wrote two of four bindings.** The replay hotkey was
never persisted and reverted to F8 on every launch. Confirmed fixed with real
data when the `%APPDATA%` migration carried all four across.

**Rebinding a hotkey fired the action instead of binding it.** Two separate
faults, one behind the other. `BeginRebind` never republished the engine
snapshot, so the poll thread stayed armed while a key was being chosen. Fixing
that exposed the second: choosing a key publishes the new binding and re-arms in
the same snapshot, at the moment the key is still physically down, so the edge
detector compared it against state primed from the *previous* binding and read a
fresh press. The loop now adopts held keys on its first armed pass without
acting on them.

**Settings resolved against the working directory.** One install read different
settings depending on how it was launched — from Visual Studio it found them,
from a shortcut it silently started from defaults and wrote a second copy. Moved
to `%APPDATA%\JinxyClicker`, with a one-time migration so upgrading does not
present as losing everything.

**`_running` was read across threads without `volatile`.**

**Shake ran with the mouse completely free.** The gate allowed an eighth of the
window as "centred", and measurement against a live client caught a free pointer
at `dx=187 dy=-101`, `dx=106 dy=82`, `dx=-127 dy=-95` — all inside that box.
Roblox's free-mouse cursors are 64×64 rather than the Windows arrow, so the
bitmap test passed too. The real signal turned out to be far sharper: a
camera-locked pointer reads *exactly* `dx=0 dy=0` against the client rectangle
and never moves off it.

**HitFix was a dead toggle.** It had a checkbox, a saved setting and a label
promising "local timing compensation for missed input", but was absent from
`ClickSettings`, so no engine thread ever saw it. Now implemented — see below.

**Ping Sync rewrote the settings file every second.** `ProbePingAsync` called
`UpdateEngineSettings` on every reply, which marks settings dirty; a probe lands
once a second, so the stats tick serialised the whole file every tick. Around
86,000 writes a day to store values nobody changed. Being `async void` is why it
went unnoticed: the method returns at the `await`, so the save check runs before
the reply lands and the dirty flag is set just after, in time for the next tick.
Measured seven writes in seven seconds before, one in ten after.

**The graphics API preference was wiped on every launch.** The Default radio
carried `IsChecked` in the markup, which raises `Checked` during XAML parsing,
and the handler applies whatever it is handed. Every start called
`ApplyGraphicsApi(null)` before the window was shown.

**A crash introduced and caught the same hour.** The shake slider handler
guarded on the *first* control of its group; the speed slider's initial value
therefore passed the guard while the readouts after it were still null, and the
constructor threw. Found by driving the sliders through UI Automation — the
compiler had nothing to say about it.

## Features added

- **Theming** — accent colour swatches, window opacity, dark and light palettes.
  The palette became `Color` resources behind `DynamicResource`, which keeps the
  brushes unfrozen and lets one assignment repaint every `StaticResource`
  consumer without touching the 207 references.
- **Recorder** — per-monitor capture via `gdigrab` cropping, shared with the
  replay buffer; a bindable record hotkey; configurable clip folder and
  framerate.
- **Settings page** — master hotkey switch, clip folder, capture framerate.
- **Corner failsafe** — clicking stops when the pointer reaches a corner of the
  desktop. Corners rather than edges, which are crossed constantly on a
  multi-monitor setup. Deliberately outside the armed check, so switching
  hotkeys off does not disable the way out.
- **Shake** — gated on the clicker running; direction values became sliders with
  typeable readouts, 0–100; a speed slider, 5–50 per second.
- **Combined keybind** — starts and stops the clicker and shake together. The
  standalone shake hotkey was removed as redundant, along with its whole path,
  since deleting only the button would have left the key still polled with
  nothing to rebind it.
- **HitFix, implemented** — floors both the press and the gap after it at 25ms. A
  client reads input once a frame, so a press shorter than that can begin and end
  between two reads. Raising the period to fit both floors lowers the delivered
  rate below the slider, which is the honest outcome: the surplus was never
  landing.
- **Mod page** — graphics API selector (D3D11 / Vulkan / OpenGL) with hardware
  detection, Roblox process priority, two more allowlisted flags, grey sky, and a
  backup of `ClientAppSettings.json` taken before the first write.
- **Optimizations** — a tweak disabling fullscreen optimisations for Roblox.
- **Installer** — Inno Setup, per-user, bundling .NET and ffmpeg. 98.8 MB.
- **App icon**, and the project renamed to JinxyClicker.

## Things measured rather than assumed

Worth recording, because in each case the intuition was wrong.

**Resource brushes are frozen.** The theming design's first mechanism was to
assign `SolidColorBrush.Color` directly. WPF freezes resource `Freezable`s
wherever it can, so this threw inside the constructor and the app died on every
launch. The `Color`-behind-`DynamicResource` indirection exists because of that.

**Registry detection of Vulkan is unreliable.** On this machine
`HKLM\SOFTWARE\Khronos\Vulkan\Drivers` does not exist in either registry view,
while `vulkaninfo` enumerates the GPU without complaint. Believing the registry
would have ruled out the backend most likely to be fastest on an AMD card. The
check now creates an instance and enumerates devices. `vulkan-1.dll` being
present proves nothing either — it ships with Windows.

**No FPS flags are allowlisted.** Confirmed against Roblox's own announcement,
not a third-party summary: the list covers geometry, rendering and one UI flag.
`DFIntTaskSchedulerTargetFps` is absent, and anything off the list "will simply
be ignored". A toggle for it would have been a second placebo one turn after
finding the first.

**Two false alarms, both my own test harness.** A reported `WindowOpacity`
clamping bug turned out to be PowerShell parsing a bare `-5` as a parameter
name; the value was `null`, deserialisation threw, and defaults loaded. A
reported orphaned ffmpeg process was a process-name search that missed the app
running as `dotnet.exe`. Both were stated as findings before being verified.

## Still open

- **`ARCHITECTURE.md` is stale.** It predates theming, per-display capture, the
  combined hotkey, the corner failsafe, `%APPDATA%` settings and the whole Mod
  page. The README points at it for internals.
- **No tests.** `CLAUDE.md` asks for them; the project has none. Six of the bugs
  above are pure logic with no UI involved — `SettingsPath` migration,
  `Displays.Match` fallback, hotkey deduplication, the palette table,
  `FastFlagStore` mutual exclusion, the HitFix arithmetic. All would be caught by
  a small test project against five classes.
- **38 silent `catch` blocks.** Every failure in the app is currently invisible.
- **The v1.0.0 release is a draft with no asset.** Attaching it is manual: the
  browser upload path caps at 10 MB against a 98.8 MB file, and the `gh` CLI is
  authenticated as a different account than the one owning the repository.
